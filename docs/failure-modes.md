# Failure modes

First written for the rules read on 27 Sep ("a written description of the failure modes you found", and a bonus for
"documenting failure modes other teams can learn from"). The rules re-read on 1 Oct have no bonus points and do not list
it as a separate deliverable; it stays as the README's "known limitations" and the source of the limits stated in
`docs/sponsor-fit.md` and in the answers themselves. Format per entry:
**what we observed → why it happens → what we did (or could not do) about it**. Entries found during the
private rehearsal are marked *(rehearsal)*; entries found inside the window are dated.

## Known before the window (from design and rehearsal)

1. **Geocoding is not ground truth** *(rehearsal, 2026-09-26)* — Nominatim resolves "Paço das Escolas, Coimbra" to the Porta Férrea, ~200 m from the courtyard; two hundred metres can move a point across a freguesia or land-cover boundary → the agent reports the geocoded point, its display name and a confidence flag as an evidence item, and asks for a map click when the address is ambiguous (several candidates, or a village name that exists in more than one municipality).
2. **A live source can be down while its catalogue entry looks fine** *(rehearsal)* — the DGT WFS for the fire-hazard map answers `GetCapabilities` but fails every `GetFeature` → the platform loads from the official zip instead; at run time the agent never depends on a live WFS, and every dataset row carries `retrieved_at` so the answer can say how old the copy is.
3. **Licence metadata disagrees between portals** *(rehearsal)* — the fire-hazard map is CC BY 4.0 on dados.gov.pt and "consultation only" in the ICNF geocatalogue → the answer's provenance shows both statements; the agent must not present a licence as a fact when its sources conflict.
4. **"Flood zone" layers are not flood extents, and even flood extents are not "safe/unsafe"** *(rehearsal)* — the first APA layer loaded held only 5 designated flood-risk blocks (ARPSI) in three regions; it was replaced by the PGRI 2nd-cycle hazard classes and per-return-period extents. Still, these maps exist only for the studied ARPSI stretches: a point outside every polygon is *not* "safe from flooding" → the agent says "not inside a mapped flood zone (APA PGRI 2022–2027, which covers only studied areas)", cites nearby historical flood marks when they exist, and never says "no flood risk".
5. **Outside the pilot regions the database is silent, not negative** *(design)* — CAOP is national, the other layers are not; a point in Porto returns a municipality and nothing else → every layer that is not loaded for that area must be listed under *unknowns*, and the agent falls back to the **global tier** (WorldCover, JRC flood, …) whose provenance says so; legal questions stay unanswerable there. Golden cases `out-001` (Porto: tier A partial), `out-002` (Madrid: tier D urban) and `out-003` (Guadarrama: tier D rural) test this.
6. **Boundary points touch several polygons** *(design)* — a point exactly on a freguesia or COS boundary intersects two features → `facts_at()` may return two rows for one attribute; the agent reports both instead of picking one silently.
7. **Municipality codes from memory were wrong 3 times out of 26** *(rehearsal)* — Mealhada, Mortágua and Terras de Bouro had wrong DICO hints; the loader's name cross-check against CAOP caught it → any code table typed by a human or a model is validated against an authoritative join before use.
8. **The PDM (municipal master plan) is the question people actually ask, and it is not loaded** *(design)* — "can I build here?" cannot be answered from the five base layers → the agent answers what it can (administration, land cover, hazards, census) and states explicitly that zoning/PDM rules were not consulted; golden case `cbr-005` tests this.

9. **A portal record with the right title can belong to someone else** *(rehearsal, 2026-09-26)* — the dados.gov.pt record "PDM - Planta de Qualificação do Solo (Ordenamento)" we had planned for Lisbon is Cascais's → before loading, check the publishing organisation and the extent; we loaded DGT's CRUS (national, per municipality) instead.
10. **Administrative codes move under statistics** *(rehearsal, 2026-09-26)* — the 2025 parish split (CAOP 2025) changed parish codes, while INE's housing prices still use the 2013 parishes → joining prices to the *current* parish silently loses or misassigns rows (2 of 140 in the pilot) → the price is joined through the census geography of the same vintage (BGRI 2021) and the evidence names the parish the figure refers to, which may differ from today's parish name.
11. **"Not published" is not zero** *(rehearsal, 2026-09-26)* — INE suppresses the median price where there were too few sales (238 of 931 values nationally; 85 of 140 published parishes in the pilot) → `facts_at()` returns the parish row as *not published* **and** the municipality value, labelled by level; the agent must not present the municipal median as the parish price.
12. **A plan class is not the plan** *(rehearsal, 2026-09-26)* — CRUS is DGT's harmonised reading of each PDM's ordinance plan (class, category, original designation, PDM date); it does not carry the PDM regulation, the constraint maps (REN/RAN, servidões) or later amendments, and PDM boundaries predate CAOP 2025, so a point near a municipal border can return classes from two PDMs → the agent says "PDM class according to CRUS (DGT), PDM of <date>; the regulation and constraints were not consulted", reports both classes at borders, and never answers "you can build". Six pilot PDMs are not re-coded to DR 15/2015 at all (CRUS keeps only their original designation, e.g. "Solo Rural - Espaços Florestais de Proteção") → the class field says *not re-coded* and the agent quotes the PDM's own wording instead of mapping it.
13. **A fire perimeter is not a burn map of the point** *(rehearsal, 2026-09-26)* — ICNF polygons are fire perimeters (with unburned islands inside) and `area_ha` is the whole fire's area; pre-2009 layers are coarse period compilations → the agent says "inside the perimeter of the <year> fire (N ha)", counts records rather than "times burned", and dates the source.
14. **A snapshot of a live source goes stale silently** *(design)* — the IPMA fire-risk index changes daily; the database keeps a dated snapshot only as a fallback → every snapshot fact carries its forecast date and the words "stored snapshot"; the agent reads the live API and, if it cannot, says which day the value is for.

15. **A share without a place misleads** *(design, 2026-09-26)* — "30 % of the plot is in a flood zone" does not say which 30 %; and a 1 % sliver at the edge is often two datasets drawn at different scales (PDM at 1:10 000–1:25 000, flood studies, a hand-drawn plot) disagreeing about a line → `facts_in()` returns the geometry of each share, the map draws it, and the agent treats tiny edge shares as possible boundary noise, saying so, instead of a finding.
16. **Census counts cannot be spread by area** *(design)* — residents live in buildings, not evenly over a subsection → plot answers give whole-subsection totals, labelled "not area-weighted".
17. **A surface model is not the terrain** *(rehearsal, 2026-09-26)* — the only open DEM without an account (Copernicus GLO-30) measures canopy and roofs; slope under a pine forest or in a town is wrong → every slope fact names the model. **Mitigated 2026-09-27:** the DGT LiDAR 2024 terrain model (10 m) is now the primary source; Copernicus answers only where the MDT has no tile (a third of Cávado, blocks not yet published by DGT) and still says it is a surface model. Measured: Paço das Escolas 26 % → 7 % (the surface model read the University buildings), Pinhal de Ofir flat share 41 % → 62 % (pine canopy). On plots of a few pixels the slope is "indicative".
18. **Classes change their meaning between editions** *(rehearsal, 2026-09-26)* — COS Série 1 (1995–2018) and Série 2 (2018–2025) use different nomenclatures → a trajectory across series is asserted only at level 1 (artificial / agriculture / forest / …); within Série 2, class by class.
19. **Rules of thumb must not sound like law** *(design, 2026-09-26)* — the intent profiles mix LEGAL thresholds (from a diploma) and TECHNICAL ones (engineering practice) → each threshold is typed; a LEGAL threshold is used as a finding only after a human marks it `validado` against the official text, otherwise it is shown as "to confirm".
20. **One feature, one region tag — wrong for data that spans regions** *(rehearsal, 2026-09-27)* — some national layers store a class as one huge multipolygon (COS 1995 "artificial territories": 22 parts from Lisbon to Braga; the COS road network; ICNF "no hazard"). The loader tagged each feature with a single region, so 63 km² of central Lisbon counted as Coimbra and "1995 coverage of Lisbon" read 37 of 100 km²; nothing failed and row counts looked right. A first diagnosis blamed the geometry engine (GEOS 3.9) and was wrong — decomposing the geometry per region showed the shape was correct and only the tag was not. Point lookups were never affected (they filter by geometry). → multi-region features are split into one copy per region; after every load the stage `qa` asserts that every geometry lies inside its tagged region and coverage is compared per region and per edition. The same check found a genuine second defect (multipolygon islands wholly outside a region were never trimmed). Lesson for the agent itself: when a number looks wrong, decompose it before naming a cause — and say which one was tested.
21. **"Not found" is not "not there"** *(design, 2026-09-27)* — REN and RAN are delimited per municipality (2026-09-27: no REN published for Condeixa-a-Nova, no RAN for Lisboa), building footprints were loaded only for the pilot regions, and REN watercourse lines are published only by some municipalities → a point outside every REN polygon is reported as "outside the REN areas of <municipality> (<diploma>)" plus what is known about watercourse lines there (none within 100 m / not published), only where that delimitation is loaded, and as "not available — not consulted" elsewhere; `constraints_grid` returns NULL (unknown), never `false`, for such cells. An "Exclusões" polygon is shown as *excluded from* the REN, not as a REN constraint.

22. **Two relief models on one map** *(rehearsal, 2026-09-27)* — in Cávado a third of the area has no published LiDAR MDT tile (whole blocks answer HTTP 404), so a grid or a plot at a block edge mixes 10 m terrain cells with 25 m surface-model cells; the step between them is a change of model, not of ground → `constraints_grid` returns `relief_source` per cell and plots use one source for all three relief facts; rules must never compare slopes across sources, and an answer that relies on the fallback says so.
23. **Water is 0 m, not "no data"** *(rehearsal, 2026-09-27)* — in the DGT MDT the sea and rivers are flat 0 m surfaces → a coastal or riverside cell's mean slope is diluted by water and the fallback never triggers at sea; slope near water is read together with land cover (COS water classes) before any rule fires.

Tier 2 — the site-selection layers of the Lisbon study area (loaded 2026-09-30; sources and counts in `data/sources.md`,
states in `data/site_profiles.json`):

24. **Absence in OpenStreetMap is not absence** *(data load, 2026-09-30; measured 2026-10-01)* — OSM is the only open source for municipal roads, power lines, substations and, outside the AML, schools, health units and stations, and its completeness varies by place and by mapper. Measured in the 18 AML municipalities: **135 of the 2 119 schools on the TML list (6 %) have no OSM education point within 200 m**. → official lists take precedence where they exist (TML schools and primary-care units in the AML; IP for the national road and rail network); an OSM fact is worded "mapped in OpenStreetMap (extract of 2026-09-29)"; a requirement that rests on OSM *absence* ("no school within 2 km", "no power line within 1 km") is stated as "none mapped in OSM", never as a finding.
25. **A substation known only by its name** *(data load, 2026-09-30)* — E-REDES publishes hosting capacity and load per HV/MV substation without coordinates; the installation code starts with the municipality's DICO. A point was added only where exactly one OSM substation with the same name lies in that municipality: **104 of the 128 installations in the study area** (a spot check of 18 matches was right in all 18); the other 24 are known by municipality only, and the column `localizacao` says which is which. → for those 24 the distance to the substation is *unknown*, never the distance to the municipality's centroid; a located one cites the name match as part of its evidence. The two E-REDES figures also answer different questions: hosting capacity is for new **generation**, load availability is headroom for **consumption** at distribution level — neither is the transmission grid, so neither decides a data centre's connection (`capacidade_consumo_rede`: not open).
26. **Noise is known in one municipality of thirty** *(data load, 2026-09-30)* — only Oeiras's strategic noise map (MER 2022, CC BY 4.0) could be loaded; Lisboa's (CC BY 4.0) is a `.7z` behind a JavaScript challenge that answers HTTP 403 to any script, and no open noise map was found for the other 28 municipalities (`data/inventory.md` §6). Inside Oeiras the Ln layer labels only its top class (">= 70 dB(A)"); classes 1–6 carry an id with no label at the source and are not inferred. → the noise requirement of the housing and school profiles is listed as *not assessable* in the coverage line outside Oeiras, never scored as quiet.
27. **Stops are not a service** *(data load, 2026-09-30)* — public transport was loaded as stops and route patterns (Carris Metropolitana, Metro de Lisboa) without timetables: the Carris Metropolitana GTFS (99 MB) has no licence on its dados.gov.pt record, and no open GTFS was found for CP, Fertagus or the ferries. → "a stop within 500 m" can be assessed; frequency and travel time by public transport cannot, and the coverage line says so (`gtfs`: partial). Rail stations outside the AML come only from OSM (entry 24).
28. **A published geometry can be wrong while its attributes are right** *(data load, 2026-09-30)* — the TML OGC API puts all 12 702 Carris Metropolitana stops on one point, (−8.1332, 39.6686): the origin of PT-TM06, i.e. (0, 0) converted as if it were metres — while each record's `stop_lat`/`stop_lon` is correct. The first load kept 50 of 12 752 stops (the Metro's) and nothing failed: the study-area filter silently dropped every stop as "outside". → points rebuilt from the attributes; after each load, rows are counted per source and a point table whose points are all identical is a failure.
29. **"Licence not stated" is not "open" — and one place's silence is not the last word** *(data load, 2026-09-30; revised 2026-10-01)* — the APA drinking-water protection perimeters and groundwater bodies (dados.gov.pt: `notspecified`) are loaded for the screening but **never shown in the demo** until APA confirms the terms. The LNEG lower-sensitivity areas were in the same state because the map service states no licence — until their own dados.gov.pt record turned up on 2026-10-01 with **CC BY 4.0**, while the LNEG geoPortal's legal notice adds "no commercial use" (and, further down, no public display without written consent). The AML schools went the other way: "not specified" on dados.gov.pt, ODbL 1.0 in the publisher's repository; and the DGEG solar plants say CC BY 4.0 on dados.gov.pt and CC BY-NC 4.0 in their own service. → every statement is recorded with where it was found (`data/sources.md`, `dataset_meta`); conflicting ones apply the stricter, as for the fire-hazard map (entry 3); a layer with no statement anywhere stays off screen; showing a layer whose terms conflict is the author's decision, not the loader's.
30. **A map service can list areas it will not draw** *(data load, 2026-09-30)* — the LNEG renewable acceleration areas (PAER; scenarios A–E of the working group created by Despacho 11912/2023) answer every query with attributes (parish, municipality, area) and no geometry, with `returnGeometry=true` too. → view-only: the acceleration-area requirement of the PV profile is *not assessable* from data (`lneg_paer`: not open) and the coverage line lists it; the loaded lower-sensitivity areas (scenarios 1–4) are a different product and are never presented as acceleration areas.
31. **A typed reader can cut the legal text the agent will quote** *(data load, 2026-09-30)* — GDAL reading GML without its XSD types each field from the *first* file; appending the second region's file into the same table cut its longer texts and decimals to those widths, with warnings and no error: an easement named "NOVO AEROPORTO DE L", diploma links cut by two characters (dead links), an obstacle-clearance height of 34.5 m stored as 34, and the CRUS municipality name cut to 8 characters. Row counts and geometry were right. → every appended GML or GeoJSON is loaded as unsized text (`-lco PRECISION=NO`; the SRUP with `GML_FIELDTYPES=ALWAYS_STRING` and no `.gfs` sidecar), the loader's "Lossy conversion" and "parsed incompletely" warnings are read as data loss, and the golden facts are compared before and after each load (0 differences after the reload).
32. **A park's figures repeat on every one of its blocks** *(data load, 2026-10-01)* — the DGEG solar plants are published as one row per park, sub-park or block, and the park-level fields (installed and connection power, total area) are copied onto every block row. Summed per row, the 16 blocks of one self-consumption plant in Moita read 879 MVA (54 912 kVA on each row — a figure that itself sits oddly with the plant's 999 kVA connection power and 1.96 ha). The first summary the loader printed made exactly that mistake. → nothing is summed per row on those fields: counts are of licensing processes (59 in the study area), areas come from the geometry (3 846 ha, no material overlap between rows), the only per-block power is `potencia_geradorkw`, and a published power figure is quoted as published, with its field name, never totalled.
